# 사주모아 UT — 참가자 단독 진행

참가자는 링크를 열어 혼자 테스트를 완료합니다. 행동과 답변은 자동으로 중앙 저장소에 모이고, 진행자는 결과 대시보드 확인과 CSV 내려받기만 하면 됩니다.

- 참가자 시작: https://wildisign.github.io/sajumoa-ut/?new=1
- 기록 없는 미리보기: https://wildisign.github.io/sajumoa-ut/?preview=1
- 진행자 대시보드: https://sajumoa-ut-results-wildisign-20261112.workspace-688975.chatgpt.site/dashboard
- 기존 진행자 주소도 대시보드로 이동: https://wildisign.github.io/sajumoa-ut/admin.html
- GitHub: https://github.com/wildisign/sajumoa-ut

## 진행자 사용

1. 대시보드에서 별도로 전달받은 진행자용 비밀번호를 입력합니다. ChatGPT 계정 로그인은 필요하지 않습니다. 비밀번호는 공개 소스가 아닌 서버 설정에서 관리합니다.
2. 열었을 때 결과를 불러옵니다. 이후 새 응답을 확인하려면 결과 새로고침을 누릅니다. 실시간 관여나 참가자 화면 조작은 필요하지 않습니다.
3. 상태·진입 경로·M1 제외 여부·답변 내용으로 필터링하고 참가자를 선택해 상세 답변과 버튼 기록을 확인합니다.
4. 참가자 요약 CSV는 한 참가자당 한 행, 상세 행동 CSV는 한 버튼 기록당 한 행입니다. 현재 필터에 맞는 기록을 엑셀이나 Google Sheets에서 열 수 있습니다.

참가자는 로그인하지 않습니다. 제출 완료 화면은 중앙 저장 승인을 받은 뒤에만 완료로 표시합니다. 연결 오류 시 임시 저장을 유지하고 재연결 뒤 자동 재전송합니다. 제출 완료 안내를 확인한 뒤 창을 닫으면 됩니다. JSON 수동 전달·가져오기는 필요하지 않습니다.

## 참여 중단과 복구

- 참여 번호는 브라우저에 남깁니다. 같은 기기·같은 브라우저에서 링크를 다시 열면 이전 기록을 이어갈지 확인합니다. `?new=1`도 기존 참여를 자동으로 지우거나 새 번호를 만들지 않습니다.
- 다른 참가자가 같은 기기를 쓸 때만 ‘다른 참가자로 시작’을 선택하고 확인합니다. 이전 기록과 미전송 대기열은 보존합니다. 이전 미완료 참여는 명시적인 참여 종료로 남깁니다.
- 상단 테스트 진행 관리에서 계속 진행·저장하고 잠시 멈추기·참여 종료를 선택합니다. 잠시 중단은 재개할 수 있으며, 종료한 참여는 다시 진행 상태로 바꾸지 않습니다. 이 관리 버튼은 M1 첫 앱 행동에서 제외하고 탭 기록에는 남깁니다.
- 갑자기 닫힌 창은 이탈로 단정하지 않습니다. 대시보드에는 ‘진행 중·미제출’과 마지막 저장 화면을 남기고, 명시적인 ‘잠시 중단’ 및 ‘참여 종료’와 구분합니다.
- 전송 전에 기록을 브라우저 대기열에 보관하고, 화면 숨김·종료 시 전송을 시도합니다. 종료 순간의 전송은 보장할 수 없으며, 다음 방문·재연결 때 이전 번호의 기록까지 재전송합니다. 제출 완료는 서버가 승인한 경우에만 표시합니다.
- 한 브라우저에서는 한 테스트 창만 작성할 수 있습니다. 다른 창은 안내로 막고, 기존 창을 닫은 뒤 이어하기를 누르면 최신 기록을 불러옵니다. 서버도 오래된 기록과 제출·종료 상태의 역행을 차단합니다.
- 표시된 모든 질문은 필수이며 공백만 적은 답변은 제출되지 않습니다. 떠오르는 내용이 없으면 ‘없어요’라고 적어도 됩니다. 화면과 서버에서 모두 검사합니다.

브라우저 저장 데이터 삭제, 시크릿 창 종료, 다른 기기·브라우저 사용 후에는 동일 참가자 자동 복구가 불가능합니다. 익명 번호는 사람의 실명이나 여러 기기를 아우르는 신원 확인 수단은 아닙니다. 전송하지 못한 채 저장소까지 삭제된 기록은 회수할 수 없습니다.

확인용 기록은 기본적으로 대시보드에서 숨겨집니다. 필요하면 게시 확인용 기록 포함을 켜세요. 실제 참가자 데이터와 구분합니다.

대시보드의 ‘참가자 화면 미리보기’를 누르면 실제 참가자와 같은 과업을 확인할 수 있습니다. 상단에 ‘미리보기 · 기록 저장 안 함’ 표시가 나오며, 답변 제출까지 진행해도 참가자 목록·브라우저 참가 기록·서버에 저장하지 않습니다. 기존 참가자가 진행 중인 탭과 동시에 열어도 참여 기록을 바꾸지 않습니다. ‘처음부터 다시’로 반복할 수 있고, 새로고침하면 처음부터 시작합니다. 참가자에게는 기본 시작 링크를 전달하세요.

## 테스트 흐름

스크리닝(이용 경험 유무와 관계없이 참여) → 시작 → 잔액 10,000 상담 모달 → 전화 시뮬레이션 → 목표 안내 → 잔액 0 모달 → 이용료 결제 화면 → 질문 → 제출 완료.

잔액 0 모달에서 이용료 결제를 바로 누르거나, X로 닫고 하단 탭을 통해 충전 화면에 진입합니다. 이용료 결제 화면을 약 2초 보여준 뒤 과업 완료 모달이 표시되고, ‘질문으로 가기’로 다음 단계로 이동합니다. 후불로 상담하기는 잔액과 관계없이 비활성화되어 있습니다. 첫 버튼과 실제 진입 경로는 별도로 남깁니다. 되돌아온 횟수는 본 과업에서만 기록합니다. 시간·성공률을 계산하지 않습니다.

혼자 진행하다 막힌 참가자는 테스트 안내의 진행이 어려워요를 누릅니다. 추가 과업 B를 안내하고, B의 데이터는 본 과업 M1에서 제외합니다. B에서 충전 경로를 찾거나 질문으로 바로 넘어갈 수 있으며, 진행자의 조작은 필요하지 않습니다.

질문은 총 4개이며, ‘아래 화면’이라는 표현과 실제 화면 캡처·크게 보기를 함께 제공합니다. 1번은 첫 행동과 선택 이유, 2번은 10,000포인트의 가치 체감(1 매우 낮음~5 매우 높음), 3번은 최소 충전금액 30,000원(VAT 별도)의 가격 체감(1 매우 저렴~5 매우 비쌈), 4번은 가격이 추가 결제 결정에 미친 영향(서술형)입니다. 이전 설문의 2번·3번 질문은 더 이상 표시하거나 필수로 받지 않습니다. 새 설문은 questionnaireVersion=3으로 구분하며 기존 제출 기록과 CSV 열은 보존합니다. 이용 경험 응답은 대시보드·CSV에 구분만 남기고 참여 종료나 M1 자동 제외에 쓰지 않습니다. 전화 화면은 04:08부터 감소하는 시뮬레이션이며, 약 2초 뒤 이용료 부족으로 통화가 끊겼다는 안내로 자동 이동합니다. 실제 전화·결제는 없습니다. 잔액 0은 수동 새로고침을 마친 상태를 전제로 합니다.

## 구성과 검증

GitHub Pages의 dist 프런트엔드 + Sites Worker/D1 중앙 저장소입니다. 설정 주소는 dist/config.js이며, 대시보드는 서버에서 비밀번호와 서명된 로그인 쿠키를 확인합니다. 비밀번호와 쿠키 서명 비밀값은 서버 환경 설정에만 두고 공개 소스에는 넣지 않습니다.

기능·복구·미리보기·비밀번호 접근 검증 결과는 output 폴더의 각 qa-report.json에 남깁니다. 중복 탭 차단, 닫은 뒤 이어하기, 중단 후 전화 상태 재개, 공백·조건부 답변 검사, 오프라인 제출 후 재방문 전송, 새 참가자 전환 뒤 이전 대기열 전송, 상태 필터·CSV를 확인합니다. 공개 페이지 게시 여부는 central-deployment.json에서 확인할 수 있습니다.

현재 중앙 서버: results-service-wildisign-20261112/ (별도 비공개 소스 저장소, GitHub Pages에 함께 올리지 않음). wildisign@gmail.com 계정이 Sites 소유자이며, 이 계정에서 서버를 수정·게시할 수 있습니다. 사용자가 기존 참가자 기록 없이 교체를 허용하여 새 서버로 전환했습니다. 기존 results-service/는 이전 서버 소스로 보존하며 새 게시에 사용하지 않습니다. 게시 정보는 central-deployment.json을 참고합니다.
